# concept-explainer：概念学习资料生成器

## 1. 这个 Skill 解决什么问题

学习一个新概念时，直接问 AI"给我讲讲 X"，得到的往往是一段零散、不可核查、看完就忘的对话。本 Skill 把"把一个概念学扎实"这件事拆成固定流程与固定产出结构，让每次学习都得到：

- 一套**分层的学习材料**（先定目标 → 再讲机制 → 再给场景 → 最后做辨析与自测）；
- 一份**可核查**的资料（每条关键论断都能追溯到真实来源）；
- 一份**适合沉淀到个人学习仓库**的文件（可被 Git 版本管理、可反复迭代）。

它强调"先理解、再判断、后记忆"，并且刻意要求产出**个人解释**而非照搬原文，帮助使用者真正学会而不是"看过"。

## 2. 适用场景

- 学习一个陌生的专业概念（课程概念、论文术语、工具名词均可）；
- 为学习仓库批量生成结构统一的概念资料；
- 考前复习：需要概念辨析清单与自测题；
- 为某个概念补充"应用场景 + 使用边界"的工程视角。

不适合：闲聊式问答（不需要固定产出时不要套用整套流程）；只想要一句话定义（直接回答即可，不必生成文件）。

## 3. 输入要求

| 输入项 | 是否必需 | 说明 |
|---|---|---|
| 概念名称 | 必需 | 如：Agent、大模型的上下文、Skill |
| 概念所属领域 | 可选 | 帮助判断术语口径，如"人工智能/大模型" |
| 学习深度 | 可选 | 入门 / 进阶 / 工程实践，默认"入门到进阶" |
| 输出格式 | 可选 | `html`（默认，便于浏览器阅读与排版）或 `markdown` |
| 输出位置 | 可选 | 默认写入当前工作区的 `learning-materials/` 目录 |

示例输入："用 concept-explainer 学习一下'向量数据库'，领域是大模型应用，输出 HTML。"

## 4. 生成步骤

1. **确认概念与口径**：先厘清该概念在指定语境下的定义（不同领域口径可能不同）；如果概念有歧义，先向用户确认或明示采用哪种口径。
2. **检索权威来源**：通过网络搜索找到 2~4 个可核查来源（官方文档、学术论文、课程讲义、权威百科优先），**逐条记录链接与检索日期**；不要凭印象编造来源。
3. **撰写学习目标与核心问题**：写出 3~5 条可检验的学习目标，以及 3~5 个驱动学习的核心问题。
4. **撰写主体内容**：按第 5 节"输出结构模板"逐节生成，其中"我的理解"必须用自己的话重新组织，不得整段照搬搜索结果。
5. **设计自测题**：出 6~10 道题（含单选/判断/简答），难度覆盖"记住 → 理解 → 应用"三个层次，并给出参考答案。
6. **对照自检清单**：按第 7 节逐项检查，发现问题当场修改。
7. **落盘输出**：把结果保存为文件（默认 HTML，见第 6 节命名），并简要汇报生成了什么、来源有哪些、需要使用者人工核查哪些点。

## 5. 输出结构模板（每份资料固定包含这些章节）

每份概念学习资料按以下顺序组织（标题可微调，章节不可缺）：

1. **概念速览卡**：一句话定义、所属领域、一句话"为什么重要"。
2. **学习目标**：学完你能做到什么（3~5 条）。
3. **核心问题**：带着这些问题去学（3~5 个）。
4. **我的理解**：用自己的话解释这个概念（可类比、可举例），体现个人消化而非照抄。
5. **核心机制 / 组成**：讲清楚它由什么构成、内部如何工作，配必要的结构说明。
6. **应用场景**：给出 1 个以上具体、真实的场景，说明"怎么用"。
7. **易混淆与使用边界**：常见误区、与相近概念的区别、什么情况下不该用它、有什么局限。
8. **自测问题**：6~10 题，含答案（可折叠）。
9. **参考资料**：真实可核查的来源链接 + 作者/机构 + 检索日期；同时注明"需要人工复核"的条目。

## 6. 输出文件命名规范

- 默认输出目录：`learning-materials/`
- HTML：`<概念英文或拼音小写用连字符>.html`，如 `vector-database.html`、`agent.html`
- Markdown：`<同上>.md`
- 若多个概念需说明相互关系的，输出 `concept-relationship.html/.md` 统一存放。

## 7. 资料来源与自检要求

### 资料来源要求
- 每条外部论断都要能对应到真实来源；**禁止编造**链接、论文标题或机构。
- 优先顺序：官方文档 > 学术论文（arXiv 等）> 权威百科/机构博客 > 个人博客。
- 来源需在"参考资料"中列出，标注检索日期；无法核实的内容必须明确写"存疑，待人工核实"。

### 自检清单（每次生成结束前必须逐条检查）
- [ ] 概念口径是否已澄清（没有歧义或已声明采用的口径）？
- [ ] 学习目标 / 核心问题是否与概念强相关、可检验？
- [ ] "我的理解"是否是自己的语言，而非原文复制？
- [ ] 机制 / 组成是否讲清"怎么工作"，有无关键步骤缺失？
- [ ] 应用场景是否具体到"谁、在什么情况、怎么用"？
- [ ] 易混淆点与边界是否真实存在、有依据，不是凑数？
- [ ] 自测题是否覆盖三个层次（记住 / 理解 / 应用）且答案正确？
- [ ] 资料来源是否全部真实可核查、已标注检索日期？
- [ ] 输出是否完整包含第 5 节全部章节？
- [ ] 是否提醒使用者对关键论断做人工复核？

## 8. 示例（本仓库作业一的调用记录）

本 Skill 在本仓库被调用过一次，生成了三份概念资料与一份关系说明，调用与核查过程记录在仓库 `README.md` 的"AI 使用与人工核查说明"中：

- 概念一：Agent → `learning-materials/agent.html`
- 概念二：大模型的上下文 → `learning-materials/llm-context.html`
- 概念三：Skill → `learning-materials/skill.html`
- 三者关系 → `learning-materials/concept-relationship.html`

把以上示例替换为任何新概念（如 RAG、Embedding、微调、Spark 等），流程与结构不变。
