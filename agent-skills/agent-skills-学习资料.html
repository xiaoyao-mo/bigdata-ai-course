01什么是 Agent Skills

Agent Skills（技能）是由 Anthropic 提出、并于 2025 年 12 月 18 日发布为开放标准的一种轻量格式，用于为 AI 智能体扩展专业能力与领域知识。

其本质定义很简洁：一个 Skill 就是一个包含 SKILL.md 文件的目录（文件夹）。这个目录里可以打包指令、可执行脚本、参考材料、模板等资源，智能体在需要时按需发现并加载它们。

「为一个智能体编写 Skill，就像为新员工编写入职指南。」—— 官方工程博客。它把"程序性知识 + 组织上下文"打包成可组合、可移植、可复用的资源，将通用智能体转变为领域专家。

它要解决的核心问题

现代通用智能体（如 Claude Code）已经具备"通过代码与文件系统完成几乎任何数字任务"的能力，但往往缺乏"把事情做对、做熟练"的专业知识。Skill 弥补的正是这个缺口——把工作流、最佳实践与领域经验固化为智能体可渐进访问并应用的文件。

四大特性（官方概括）：

  • Composable（可组合）：多个 Skill 可以叠加协作，智能体自动识别并协调使用。
  • Portable（可移植）：同一格式在所有产品中通用——一次构建，跨 Claude 应用、Claude Code 与 API 复用。
  • Efficient（高效）：只在需要时加载所需内容，保护上下文窗口。
  • Powerful（强大）：可包含可执行代码，用于传统编程比 token 生成更可靠的确定性任务。

02渐进式披露：核心设计原则

Progressive Disclosure（渐进式披露）是让 Agent Skills 保持灵活与可扩展的核心设计原则。它的思想是：像一本组织良好的手册——先看目录，再翻具体章节，最后才查详细附录——智能体只在需要时才加载信息，而不是一次性把所有内容塞进上下文窗口。

这带来的关键结论是：一个 Skill 可以捆绑的上下文量"实际上没有上限"——因为未被访问的文件不消耗任何 token。

三个层级

层级内容加载时机Token 成本
第 1 级元数据（name + description）启动时始终加载每个 Skill 约 100 token
第 2 级指令（SKILL.md 正文）Skill 被触发时通常 < 5k token
第 3 级及以上资源与代码（捆绑文件）按需访问时访问前为零

第 1 级元数据会进入系统提示（system prompt），其中的 description 是智能体判断"是否触发该 Skill"的唯一匹配依据。因此一个轻量的第 1 级设计，让你可以安装大量 Skill 而不产生上下文惩罚。

三种内容类型，各司其职

类型作用优势
指令 Instructions工作流、最佳实践、逐步指导灵活指导
代码 Code可执行脚本（如 fill_form.py）确定性、可靠性
资源 Resources数据库模式、API 文档、模板、示例事实查询

03Skill 的目录结构

一个 Skill 的最小构成是单个 SKILL.md 文件。更复杂的 Skill 可以捆绑额外文件：

pdf-processing/
├── SKILL.md        # 主要指令（必填）
├── FORMS.md        # 表单填写指南（按需加载）
├── REFERENCE.md    # 详细 API 参考（按需加载）
└── scripts/
    └── fill_form.py # 可执行脚本（确定性操作）

SKILL.md 的骨架

每个 SKILL.md 必须以 YAML frontmatter 开头，包含必填的 name 与 description：

---
name: pdf-processing
description: Extract text and tables from PDF files, fill forms, merge documents. Use when working with PDF files or when the user mentions PDFs, forms, or document extraction.
---

# PDF Processing

## Quick start
Use pdfplumber to extract text from PDFs:
...

## Form filling
See FORMS.md for the form-filling reference.
加载过程（示例）：启动时系统提示只包含 name 与 description；当用户请求「提取这个 PDF 的文本」时，智能体用 bash 执行 cat SKILL.md 加载正文；若任务不涉及填表，则不会去读取 FORMS.md。

04元数据字段规范

元数据写得是否规范，直接决定 Skill 能否被正确发现与触发。官方对两个必填字段有明确约束：

字段约束
name 最多 64 个字符；只能包含小写字母、数字和连字符（-）；不能包含 XML 标签；不能包含保留字 anthropic 或 claude。
description 不能为空；最多 1024 个字符；不能包含 XML 标签；必须同时说明「该 Skill 做什么」以及「何时使用它」。
易错点：description 是智能体判断是否触发的唯一依据。一个只写功能、不写触发条件的描述（如 "Helpful tool for documents"）会导致 Skill 无法被正确触发。

05Skill vs Prompt vs MCP

理解 Skill 与其他扩展机制的区别，是正确选用它的前提。

机制定位加载方式典型场景
Prompt对话级指令，一次性任务每次对话手动/临时写入一次性的提问、翻译、临时要求
Skill文件系统级、可复用的流程化专业知识按需自动发现与加载反复执行的领域工作流、组织规范
MCP连接外部工具与数据源的协议建立连接后供模型调用接入数据库、第三方 API、本地应用

一句话概括：Prompt 处理一次性指令，Skill 封装可复用的"怎么做"，MCP 负责连接外部的"用什么工具/数据"。Skill 与 MCP 可以互补——例如一个 Skill 的脚本里可以通过 MCP 连接的数据源完成分析。

06代码执行与确定性

Skill 可以包含可执行代码，让智能体在代码执行环境（沙盒虚拟机，具备文件系统访问权限）中运行脚本。这一点很关键：

  • 确定性：对列表排序这类任务，运行一段排序算法远比靠 token 逐个生成结果更可靠、更省成本。
  • 不占上下文：脚本源码本身永远不会进入上下文窗口——智能体通过 bash 运行脚本，只有输出（如 "Validation passed" 或错误信息）进入上下文。
  • 可重复：因为代码是确定的，工作流保持一致、可复现。
架构要点：Skill 在虚拟机上以目录形式存在，智能体用与你浏览文件相同的 bash 命令（cat、ls、运行脚本）与之交互。

07安全注意事项

Skill 通过指令与代码赋予智能体新能力，这意味着恶意 Skill 可能引导智能体以与声明用途不符的方式调用工具或执行代码。官方明确要求：

  • 只使用可信来源：自己创建的、或来自 Anthropic 官方的 Skill。
  • 彻底审查：检查 Skill 中捆绑的所有文件——SKILL.md、脚本、图像及其他资源，留意意外的网络调用、文件访问模式或与声明用途不符的操作。
  • 警惕外部 URL 取数：从外部 URL 获取数据的 Skill 风险最高，因为获取的内容可能包含恶意指令；可信 Skill 的外部依赖也可能随时间被攻破。
  • 像安装软件一样对待：集成到能访问敏感数据或关键操作的生产系统前要格外谨慎。

08可用平台与生态

  • Claude 应用（claude.ai）：Pro/Max/Team/Enterprise 用户可用；文档创建类 Skill 开箱即用。
  • Claude Code：将自定义 Skill 放在 ~/.claude/skills/（个人）或 .claude/skills/（项目）即可被自动发现；可通过插件安装。
  • Claude API / Claude Agent SDK：通过 /v1/skills 端点管理，或引用预构建 Skill（pptx、xlsx、docx、pdf）。
  • 开放标准：格式已在 agentskills.io 发布为开放标准，被 GitHub Copilot、Cursor、Gemini CLI、OpenAI Codex 等三十余款智能编码工具采纳。
