Agent（智能体）

生成方式：concept-explainer Skill · 领域：人工智能 / 大语言模型应用
AI AgentLLM 应用生成日期 2026-09-06来源核查 2026-09-06

0概念速览卡

Agent（智能体）＝能够自己决定"下一步做什么"的 AI 系统：它由一个或多个大语言模型作为"大脑"，在目标的引导下自主规划、调用工具、观察结果并循环推进，直到任务完成——而不是按人事先写死的步骤机械执行。

一句话为什么重要：大模型本身只会"生成文字"，而 Agent 让它从"会说话"变成"会办事"，是当前 AI 从问答工具走向生产力的关键形态。

1学习目标

  • 能用一句话说清 Agent 与大模型、聊天机器人、工作流（Workflow）的区别。
  • 能说出一个典型 Agent 由哪几部分组成，并画出"观察→规划→行动→再观察"的循环。
  • 能判断一个具体需求"该用 Agent 还是简单方案"，并说明理由。
  • 能列举 Agent 的常见失败方式与使用边界，并给出至少一种防护思路。

2核心问题

  1. Agent 与"按流程跑的工作流"本质差别是什么？
  2. 模型凭什么能"调用工具"？工具结果又是如何回到模型手里的？
  3. Agent 会"记住"之前做过的事吗？它靠什么维持多步任务的状态？
  4. 什么时候不该用 Agent？

3我的理解

我把 Agent 比作一名被授权的实习生：你有明确目标（"把这 30 份报表分析完"），但不会手把手告诉他每一步。他会自己判断：先打开哪份、用什么工具算、中间结果不对劲时换个方法，做完了向你汇报。与之相对，普通聊天机器人像"复读机+资料员"——你问一句它答一句；工作流（Workflow）像"有轨电车"——轨道（代码）铺到哪它开到哪。

Anthropic 在《Building Effective Agents》里给过一个非常干净的划分：所有"大模型+工具"的系统都叫 agentic systems，但按"控制权在谁手里"分成两类——Workflow：控制权在代码（步骤预先写死，模型只做单步推理）；Agent：控制权在大模型（模型动态决定自己的流程与工具调用）。我理解 Agent 的本质不是"用了大模型"，而是把流程控制权交给了模型。

个人补充：自主程度其实是个光谱——从"单次工具调用"到"长周期自主运行"都算 agentic。讨论时先问一句"谁在决定下一步"，很多争论会立刻消失。

4核心机制 / 组成

Anthropic 给出的最小构建块叫增强型大模型（Augmented LLM）：模型 + 检索（RAG）+ 工具（Tools）+ 记忆（Memory），这也是 Agent 的四块地基。

组成部分作用通俗类比
大模型（推理内核）理解目标、做计划、决定下一步、生成输出大脑 / 判断力
工具（Tools / Function calling / MCP）让模型能查库、算数、上网、操作文件等；模型通过"函数调用"请求执行并把结果拿回上下文手和腿
记忆（Memory）短期＝上下文窗口内信息；长期＝外部存储（数据库、向量库）按需检索回来工作台便签 + 档案柜
检索（RAG）把外部知识（文档/数据库）检索后拼进上下文，弥补模型知识不足现查资料

关键点：工具结果会回到上下文窗口，模型"看到"结果后决定是否继续或结束——循环的动力来自上下文信息的流动（与概念资料《大模型的上下文》直接相关）。

5应用场景（真实具体）

场景一：数据分析 Agent

分析师问 Agent："帮我查 Q2 华南区销量为什么下滑。" 一个典型的执行轨迹是：① Agent 决定先写 SQL 查销售库 → ② 工具返回发现某月数据大量为空 → ③ Agent 改为调用 Python 清洗并对比去年同期 → ④ 生成趋势图与归因结论，向人汇报。整个过程没有人为每一步编程，每一步由模型根据上一步结果临场决定。

场景二：客服 / 编码 / 研究等通用领域

Anthropic 观察到生产环境中 Agent 最成功的用法是"简单可组合的模式"，常见落地领域包括客服自动处理、代码仓库级开发、信息检索研究等；其要点都是"先给模型明确目标 + 必要工具，再让它自主推进"。

6易混淆与使用边界

易混淆概念区别一句话
Agent vs 聊天机器人聊天机器人只生成回复；Agent 能自主调用工具并采取行动完成任务。
Agent vs Workflow（工作流）工作流步骤由代码预定义；Agent 步骤由模型动态决定（控制权归属不同）。
Agent vs 多智能体系统Agent 是单体的能力单元；多智能体是多个角色协作的编排形态，不等于"更高级的 Agent"。
Agent vs "增强型 LLM"增强型 LLM（模型+检索+工具+记忆）是地基；Agent 是建立在地基上、拥有自主控制循环的系统。

使用边界（什么情况下别急着上 Agent）

  • 能用更简单方案就别用：Anthropic 明确建议先从最简单的单次调用 + 检索做起，只有需要"模型自主决策路径"时再升级。
  • 代价：Agent 用延迟和 token 成本换灵活性；高频、低延迟、预算敏感的场景慎用。
  • 可靠性：模型可能幻觉或错误使用工具，且错误会在循环中被放大；涉及钱、隐私、人身安全的操作必须加护栏（权限最小化、人工确认、最大步数、终止条件）。
  • 上下文限制：长任务中信息可能超出窗口或"迷失在中间"，需要压缩/检索等上下文管理。

7自测问题

1.（判断）只要用了大模型 API 并且接了工具，这个系统就一定是 Agent。
错误。是否 Agent 看"控制权"：如果步骤由代码写死、模型只做单步推理，那是 Workflow；模型自主决定流程与工具调用才是 Agent。
2.（单选）Agentic Loop 中，让模型能"看到"工具执行结果并据此决定下一步的机制是：A. 模型参数更新 B. 把工具结果放回上下文窗口 C. 重新训练 D. 数据库触发器
B。工具结果作为新的输入放回上下文，模型据此继续推理（这正是"上下文"概念的用武之地）。
3.（多选）典型 Agent 的组成通常包括：A. 大模型 B. 工具/函数调用 C. 记忆或检索 D. 预定义的全部执行分支
A、B、C。D 是 Workflow 的特征，不是 Agent 的必要组成。
4.（简答）"给模型一个目标，它自主决定步骤"描述的是 Workflow 还是 Agent？为什么这个划分有意义？
Agent。划分的意义在于提醒开发者先想清楚"把多少决策权交给模型"：决策权越大越灵活，但不确定性、成本与调试难度也越高。
5.（判断）Agent 出现一次幻觉错误没关系，反正是它自己循环。
错误。错误会被循环放大，长时间自主运行的 Agent 需要护栏（人工介入点、终止条件、权限限制）。
6.（简答）举一个"看起来像 AI 功能、但其实不需要 Agent"的例子，并说明你会用什么替代。
示例：把用户问题分类后走固定分支（如"查天气→调天气 API→固定格式返回"）用 Routing 工作流即可，甚至单次调用+检索就够。原则：先最简单，按需增加复杂度。
7.（单选）模型"调用工具"通常依赖哪种能力：A. 函数调用（Function calling）B. 向量检索 C. 提示词缓存 D. 微调
A。模型输出结构化的工具调用请求，由运行环境执行并把结果交回。
8.（简答）说说 Agent 的"记忆"为什么是个容易误会的点。
模型本身无状态，"记性"来自上下文：短期记忆是当前窗口里的信息；长期记忆靠外部存储检索回来再放进上下文。会话一旦结束、信息一旦超出窗口，就等于"忘了"。（详见概念 2 的资料。）
